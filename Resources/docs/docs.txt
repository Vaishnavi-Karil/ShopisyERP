Agar tum **production-ready eCommerce Backend** bana rahi ho (Amazon/Flipkart style), to routes ko CRUD aur business operations ke hisaab se design karo.

---

# 1. Auth Routes

Base Route:

```text
/api/auth
```

| Method | Route                  | Purpose                      |
| ------ | ---------------------- | ---------------------------- |
| POST   | `/register`            | Register new user            |
| POST   | `/login`               | Login                        |
| POST   | `/logout`              | Logout                       |
| POST   | `/refresh-token`       | Generate new access token    |
| POST   | `/forgot-password`     | Send reset password link/OTP |
| POST   | `/reset-password`      | Reset password               |
| POST   | `/verify-email`        | Verify email                 |
| POST   | `/resend-verification` | Resend verification email    |

---

# 2. User Routes

Base Route:

```text
/api/users
```

| Method | Route              | Purpose                  |
| ------ | ------------------ | ------------------------ |
| GET    | `/profile`         | Logged-in user's profile |
| PUT    | `/profile`         | Update profile           |
| PUT    | `/change-password` | Change password          |
| DELETE | `/profile`         | Delete own account       |
| GET    | `/`                | Get all users (Admin)    |
| GET    | `/:id`             | Get user by ID (Admin)   |
| PUT    | `/:id`             | Update user (Admin)      |
| DELETE | `/:id`             | Delete user (Admin)      |

---

# 3. Category Routes

Base Route:

```text
/api/categories
```

> Main recommendation: route ko plural (`categories`) rakho. Ye REST convention hai.

| Method | Route                | Purpose                  |
| ------ | -------------------- | ------------------------ |
| POST   | `/`                  | Create category          |
| GET    | `/`                  | Get all categories       |
| GET    | `/tree`              | Get nested category tree |
| GET    | `/:id`               | Get category by ID       |
| PUT    | `/:id`               | Update category          |
| DELETE | `/:id`               | Delete category          |
| GET    | `/:id/subcategories` | Get direct subcategories |

---

# Meri recommendation

Tum abhi **MongoDB, Mongoose, Authentication, Authorization, Aggregation, Production APIs** seekh rahi ho.

Is stage par **Catalog + Seller Listing architecture mat implement karo**.

Pehle ye complete karo:

```
User
Category
Product
Cart
Order
Wishlist
Review
Payment
Address
```

Aur `Product` me `sellerId` rakho.

Jab ye project complete ho jaye aur tum advanced marketplace version banana chaho, tab hum `Product` ko do collections me tod denge:

* **Product Catalog**
* **Seller Listing**

Ye migration bhi main step-by-step sikhaunga.

**Meri advice:** Tumhare current learning stage ke liye **single `Product` collection + `sellerId`** bilkul sahi aur production-quality design hai. Jab marketplace scaling ka topic aayega, tab Catalog + Seller Listing architecture par move karna natural next step hoga.
